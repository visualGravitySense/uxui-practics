UX-АУДИТ · СПИСОК ИНСТРУКТОРОВ (Instruktorid)

Где именно ломается решение забронировать инструктора

Разбор карточек инструкторов по модели поведения BJ Fogg (Motivation × Ability × Prompt) и по воронке действия CREATE, с приоритезированным списком проблем и техзаданием на редизайн.

Экран — вкладка «Instruktorid», сетка из 6 карточек
Модели — Fogg Behavior Model, CREATE Action Funnel
Цель — рост конверсии в бронирование
1 Аудит по Fogg Behavior Model

Motivation × Ability × Prompt

По Fogg, действие происходит только когда мотивация, способность выполнить действие и триггер (prompt) совпадают в один момент. Ниже — что в текущем экране поддерживает каждый компонент, а что его подрывает.

Motivation хочу забронировать именно этого

＋Цена, фото и короткое описание видны сразу — базовый материал для решения есть.
✕У всех шести карточек рейтинг «5.0» без числа отзывов — сигнал обнулён: сравнить инструкторов по качеству невозможно, все выглядят одинаково сильными.
✕Бейджи «Elite Instructor» / «Verified Pro» стоят только у части карточек (Алексей, Иван, Андрей, Станислав), у Игоря и Вейко их нет — непонятно, это осознанный статус или недоработка данных, доверие к системе бейджей падает.
!Плашка «70% с 1. попытки» / «60% с 1. попытки» — сильный мотиватор (сдал с первого раза), но показана только у 2 из 6 карточек без объяснения, что это за метрика.

Ability легко ли принять решение

✕Описание обрезано многоточием почти у всех карточек — чтобы дочитать, нужно уйти с экрана списка, теряя контекст сравнения.
✕Нет фильтра и сортировки в этой зоне экрана (по цене, языку, коробке передач, району) — сравнение 6 карточек делается вручную, глазами.
!Теги языка и коробки передач («MANUAL», «RU», «EE») мелкие и низкоконтрастные — легко принять за декоративный элемент, а не за критерий выбора.
!Нигде не видно ближайшего свободного слота — чтобы узнать, когда реально можно поехать, нужно открыть профиль.

Prompt что подталкивает нажать

✕Кнопка «BRONEERI» залита синим только на первой карточке (Алексей Йесков), на остальных пяти — контурная, белая. Главное действие выглядит разным по значимости от карточки к карточке.
!Непонятно, ведёт ли «BRONEERI» сразу в календарь бронирования или на страницу профиля — обещание кнопки неоднозначно.
!Внизу экрана два CTA одинакового визуального веса — «Смотреть всех инструкторов» и «Подобрать через тест» — конкурируют, а не дополняют друг друга.
Итог по Fogg: мотивация есть, но неотличима между карточками; способность принять решение снижена нехваткой данных прямо в карточке; триггер (кнопка) слабый и непоследовательный именно там, где нужен самый ясный сигнал — в момент выбора.
2 Аудит по CREATE Action Funnel

Cue → Reaction → Evaluation → Ability → Timing → Execution

Каждый этап — точка, на которой пользователь может выйти из воронки. Ниже — что происходит на каждом шаге на этом экране.

01

Cue

Активная вкладка «Instruktorid» и сетка карточек ясно сообщают: здесь выбирают человека, а не пакет услуг.

Работает
02

Reaction

Первая, инстинктивная реакция должна отсеять слабые варианты. Но одинаковый рейтинг 5.0 у всех карточек не даёт глазу зацепиться ни за одну.

Ломается
03

Evaluation

Осознанное сравнение цены, языка, авто требует дочитывать обрезанные описания и держать в голове 6 карточек без таблицы сравнения.

Ломается
04

Ability

Кнопка «BRONEERI» физически доступна, но без данных о ближайшем слоте пользователь не уверен, что бронирование вообще возможно сейчас.

Ослаблена
05

Timing

Нет ни одного сигнала срочности или своевременности («свободен сегодня», «осталось 2 места на неделе») — мотивированный пользователь откладывает решение «на потом».

Ломается
06

Execution

Непоследовательный стиль кнопки на 5 из 6 карточек снижает аффорданс — контурная кнопка читается менее кликабельной, чем залитая.

Ослаблена
Итог по CREATE: воронка ломается уже на Reaction и Evaluation — то есть до того, как пользователь вообще доходит до кнопки. Даже идеальная кнопка не спасёт конверсию, если решение не вызрело на шагах 2–3 и 5.

4 Техническое задание

ТЗ на редизайн блока «Instruktorid»

Цели редизайна

  • Поднять долю пользователей, доходящих от списка до нажатия «Забронировать», за счёт устранения обрывов на Reaction и Evaluation.
  • Сделать карточки сравнимыми между собой без перехода в профиль.
  • Дать пользователю однозначный, узнаваемый визуальный сигнал главного действия на каждой карточке.
  • Снизить долю отказов на этапе Timing, показывая реальную доступность инструктора.

Целевое поведение пользователя

Пользователь открывает список → за 1–2 карточки понимает, чем инструкторы отличаются друг от друга → сужает выбор фильтром или визуальным сравнением до 2–3 кандидатов → видит ближайшее свободное время прямо в карточке → нажимает единообразную кнопку «Забронировать» и без сомнений переходит к оформлению записи.

Убрать

  • Единичную залитую кнопку на одной карточке — как исключение из общего стиля.
  • Жёсткое обрезание описания без возможности раскрыть его в списке.
  • Молчаливое отсутствие бейджа/метрики там, где данных просто нет (заменить на явный нейтральный статус, а не пустоту).

Добавить

  • Числовой рейтинг с количеством отзывов: «4.8 (126 отзывов)» вместо плоского «5.0».
  • Блок ближайшей доступности прямо в карточке: «Свободен сегодня, 16:00» / «Ближайшее время: ср».
  • Панель фильтра и сортировки над сеткой: цена, язык, коробка передач, район, рейтинг, доступность.
  • Легенду/тултип для бейджей и метрики «% с первой попытки», доступную по иконке ⓘ.
  • Возможность раскрыть описание по клику «читать полностью» вместо ухода со страницы.

Изменить

  • Кнопку «BRONEERI» — единый залитый стиль на всех карточках без исключений; вторичное действие «Профиль» — текстовой ссылкой рядом.
  • Бейджи статуса — показывать по единому правилу для всех инструкторов, соответствующих критерию, без «случайных» пропусков.
  • Вес двух нижних CTA — оставить «Смотреть всех инструкторов» основным действием, «Подобрать через тест» сделать явно вторичным (менее контрастным) как путь для тех, кто не определился.
  • Контраст и размер тегов языка/коробки — поднять до уровня читаемого критерия выбора, а не мелкой подписи.

Принципы дизайна

Один явный сигнал действия

На каждой карточке должно быть ровно одно визуально доминирующее действие — без исключений и без конкуренции по весу.

Сравнимость по умолчанию

Все карточки показывают одинаковый набор полей в одинаковом порядке — сравнение не должно требовать перехода вглубь.

Прозрачность метрик

Любая цифра или бейдж на карточке объясняет себя за один клик или наведение — никаких «магических» пятёрок и значков без расшифровки.

Доступность вместо догадки

Информация, нужная для решения «можно ли записаться сейчас», видна в карточке, а не только внутри профиля.

Требования к компонентам

  • Карточка инструктора должна одинаково вести себя в состояниях: с бейджем / без бейджа, с плашкой первой попытки / без неё, с длинным / коротким описанием — без визуальных «дыр».
  • Кнопка «Забронировать» — один компонент, одно состояние по умолчанию (залитая), hover/focus/disabled определены явно, используется без вариаций по карточкам.
  • Блок доступности — отдельный компонент с минимум двумя состояниями: «свободен сегодня» (акцентный цвет) и «ближайшее время такого-то дня» (нейтральный).
  • Панель фильтров — работает как отдельный, самостоятельно тестируемый блок, не завязанный жёстко на конкретную сетку карточек.
  • Бейдж и тултип — бейдж как атом, тултип/легенда как отдельный переиспользуемый компонент пояснения.
